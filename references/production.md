# 편집과 파일 전달

## 최근 제작 흐름

주제 후보 10개에서 사용자가 선택하면 첫 3초 훅과 기승전결, 장면 수와 예상 비용을 먼저 설명한다. 기본은 8초 클립 5개이며 컷 분할·재사용·설명 구간으로 45초를 구성한다. 읽어야 하는 문구와 내레이션은 충분한 시간을 준다. 제작 과정 화면녹화를 요청받은 경우에만 대기 구간을 강하게 가속하고, 뉴스·메시지를 읽는 구간은 천천히 보여 준다.

Flow에서 모델·360p·생성 개수와 비용을 확인한다. 동일성이 필요한 인물·동물은 기준 이미지를 실제 첨부한다. 생성 360p와 서비스에서 실제 업스케일한 720p를 `assets/360p`, `assets/720p`에 각각 저장한다. 현재 기본값은 360p 생성 → 실제 720p 업스케일이다. 최종 편집 캔버스는 1080×1920을 유지하며 이는 720p 소스의 확대 출력이다. 생성 비용과 업스케일 비용은 현재 UI를 확인하며 과거 단가를 고정값으로 사용하지 않는다.

Hypit 프로젝트가 있으면 `assemble.py`, `film.svml`, `film.svs`, `build.svrun`, `voice-timing.json` 등 실제 파일을 재사용한다. Hypit의 Hyperframes 렌더 경로로 편집하고 독립 HTML 프로젝트로 재작성하지 않는다. 아래 HTML 계약은 직접 Hyperframes HTML을 만드는 경우에만 적용한다. 과거 템플릿의 AI 고지 자막·예전 소재를 새 영상에 그대로 복사하지 않는다.

음성은 선택한 서비스와 기존 승인 목소리를 사용한다. 최근 ElevenLabs 제작 예시는 `eleven_v3`와 발화 정렬 데이터를 사용했다. 기존 정렬과 원본 재생속도를 먼저 확인하고 이미 편집된 음성에 1.2배속을 추가 적용하지 않는다. 새 음성은 저장된 속도 설정과 사용자의 지시를 따른다.

## 생성 전에 구도를 설계하기

스토리보드에 각 장면의 목적, 피사체 행동, 촬영 거리, 각도, 배경, 카메라 움직임을 짧게 적는다. 이 차이를 각 생성 프롬프트에 명시하고, 모든 프롬프트에 같은 side profile / close-up / forest bokeh를 반복하지 않는다.

예: 서식지의 넓은 장면 → 나무를 쪼는 사선 전신 → 부리 접촉 부위의 초근접 → 머리 구조 개념도 → 망치 비교 → 아래에서 올려다본 마무리. 주제에 맞는 예시이며 모든 영상에 같은 순서나 개수를 강제하지 않는다. 카메라를 움직이는 것만으로 장면 다양성을 대신하지 않는다.

생성·편집 후 장면별 대표 프레임을 나란히 보고 같은 실루엣·거리·배경이 반복되는지 확인한다. 반복 장면은 다른 행동·각도의 원본으로 교체한다. 대본에 필요한 연속 동작은 유지하고, 새로운 구도를 위해 사실에 없는 행동이나 구조를 만들지 않는다.

## 원리·구조 시각화

스토리보드에서 원리나 구조를 설명하는 구간을 표시하고, 시청자가 이해해야 할 관계와 그것을 보여 줄 표현 방식을 함께 정한다. 해당 시각 자료를 실제로 만들어 최종 영상에 삽입한다. 풍경·피사체 사진에 설명 자막만 붙이는 것으로 이 구간을 대신하지 않는다.

- **2D 도해·단면도:** 내부 구조, 힘의 방향, 단계별 과정을 선·화살표·강조 영역으로 보여 준다. 평면만으로 충분하면 2D를 우선한다.
- **3D 구조·동작:** 깊이, 공간 배치, 회전, 궤도처럼 입체 관계가 핵심일 때 사용한다. 필요한 부분을 회전·분해·단면으로 보여 주고 장식적인 카메라 움직임은 줄인다.
- **그래프:** 시간에 따른 변화나 양의 관계를 설명할 때 사용한다. 실제 수치에는 출처·축 이름·단위를 붙이고, 확인하지 않은 수치나 정밀도를 만들지 않는다. 정성적인 개념 곡선은 그 사실을 표시한다.
- **비교표:** 두 대상이나 조건의 차이를 한눈에 보여 줄 때 사용한다. 모바일 화면에서 읽을 수 있는 소수의 항목만 남기고, 현재 설명하는 행을 강조한다.
- **시뮬레이션:** 조건이 바뀌었을 때 결과가 어떻게 달라지는지 움직임으로 보여 준다. 단순 설명 애니메이션은 제작정보에 설명용 모식도임을 기록하고, 화면에서 실제 측정과 혼동될 때만 짧은 표시를 추가한다. 실제 계산을 수행한 경우에만 물리 계산 결과로 설명한다. 계산 모델의 가정과 단순화는 제작정보에 기록한다.

한 설명 장면에는 한 가지 핵심 관계를 담고, 내레이션에서 언급하는 순서에 맞춰 요소를 강조한다. 실제 피사체 → 설명 시각화 → 실제 장면의 흐름을 내용에 맞게 활용한다. 기존 Hyperframes/SVG/GSAP 구성과 설치된 도구를 재사용하며, 글자·숫자·축·단위는 편집 가능한 요소로 작성한다. 최종 렌더에서 화살표 방향, 크기 비교, 자막과의 겹침, 설명과 동작의 타이밍을 직접 확인한다.

## 최소 Hyperframes 계약

호환 기준은 실제 제작에 사용한 CLI 0.8.35다. 설치된 CLI의 `--help`와 `docs`를 먼저 확인한다. 기존 편집 파일이 있으면 새 도구나 추상 구조를 만들지 말고 그것을 수정한다.

- 루트에 `data-composition-id`, `data-width="1080"`, `data-height="1920"`, `data-duration`를 선언한다.
- `class="clip"`, 고유 `id`, `data-start`, `data-duration`, `data-track-index`로 장면을 배치한다.
- GSAP을 사용한다면 paused timeline 하나를 `window.__timelines[compositionId]`에 등록한다. 시간·난수에 따라 매번 달라지는 애니메이션을 쓰지 않는다.
- `<video>`는 `muted playsinline`. 소리는 별도 `<audio id="...">`로 배치한다. 음성 id가 없으면 믹스에서 빠질 수 있다.
- SVG 중첩 그룹의 날개/부위 애니메이션은 원래 좌표를 보존한다. 로컬 `attr.transform`과 전역 `svgOrigin`을 혼동하면 부위가 몸에서 분리될 수 있으므로 최종 프레임에서 연결 상태를 확인한다.
- 일반 `data-start` 래퍼 안에 다시 `data-start`가 있는 video를 넣지 않는다. 타이밍은 한 계층에만 둔다. 영상 전환은 시간 속성이 없는 래퍼를 움직인다.
- HTML에서 media의 play/pause/currentTime을 직접 제어하지 않는다. 엔진이 재생·추출을 소유한다.
- video/audio에 불필요한 `crossorigin`을 붙이지 않는다.
- 생성 원본보다 긴 슬롯을 만들지 않는다. 지원되는 재생 속도 또는 FFmpeg 전처리를 사용하고 시간을 다시 확인한다.
- 별도 지정이 없으면 스킬의 `assets/music/` 기본 WAV를 사용한다. 음악은 정상 속도로 영상 길이만큼 반복하며 -28 LUFS를 출발점으로 말보다 작게, 환경음은 대사를 가리지 않게 섞는다. atempo 사용 시 실제 출력 길이를 다시 측정한다.

## 기존 자막 기준

배경 상자는 사용하지 않는다. “AI 연출”, “AI로 생성한 영상입니다” 같은 고지 화면 자막은 넣지 않는다. 설명란·YouTube 합성 콘텐츠 설정은 내용에 맞게 유지한다. 최근 Hypit 예시의 자막 영역은 1080×1920에서 x=60–1020, y=1370–1585, 글자 56px·외곽선 4px이다. 기존 영상에 맞게 조정하며 아래 직접 HTML 예시는 고정 규격이 아니다.

1080×1920 기준: 폭 970px, left 55px, top 약 1640px, 글자 약 62px, 검은 테두리 약 7px, `paint-order: stroke fill`, 굵은 Pretendard Bold 또는 사용자가 지정한 폰트. 긴 문구는 분할하여 화면 밖으로 나가지 않게 한다. 기준 영상이나 플랫폼 UI 안전 영역에 맞춰 조정한다. 폰트는 설치된 파일 또는 사용 가능한 라이선스의 파일을 구해 프로젝트에 저장한다.

전환은 비시간 래퍼에 scale 약 1.12 → 1, blur 약 15px → 0, 약 0.32초. 첫 장면은 즉시 선명하게 보여 준다. 출처와 설명용 도식의 가정은 제작정보와 영상 설명에 남긴다. 사용자가 원하지 않는 제작·검토 안내 문구를 영상에 추가하지 않는다.

## 실행 명령

프로젝트 자체 엔진이 있으면 그 엔진을 사용한다. 아래 HF는 기존 프로젝트의 CLI 절대 경로로 바꾼다. `--setup-runtime`을 선택한 경우에만 예시 경로에 엔진이 준비된다.

```bash
HF="$HOME/.local/share/hyperframes/runtime/node_modules/.bin/hyperframes"
PROJECT="$HOME/Projects/Youtube/영상 제목"
"$HF" check "$PROJECT" --json
"$HF" render "$PROJECT" --quality high --fps 30 --workers 1 --low-memory-mode --output "$PROJECT/영상 제목.mp4"
ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate:format=duration -of json "$PROJECT/영상 제목.mp4"
ffmpeg -v error -i "$PROJECT/영상 제목.mp4" -f null -
```

필요할 때 로컬 미리보기 서버를 사용한다. 사용 중인 포트를 종료하지 말고 빈 포트를 선택한다. 브라우저 파일 재생이 지원되면 서버는 필요 없다.

## 웹 서비스에서 저장

생성 완료 후 서비스의 공식 다운로드 버튼을 사용한다. 저장 대화상자는 웹 DOM에 안 보일 수 있으므로 네이티브 앱 상태를 확인한다. 원하는 제목 폴더의 assets 경로와 파일명을 지정하고 실제 파일 생성·미디어 정보를 확인한다. 다운로드 클릭만으로 저장 완료라고 말하지 않는다. 컴퓨터 사용 도구의 허용 범위를 따른다.

## 제작정보에 남길 내용

실제 제공 서비스·모델·해상도·원본 길이, 사용 목소리, 장면별 소스 파일, 출처와 과학 주장 범위, 생성 이미지의 한계, 자막 정렬 방식, 최종 출력 규격을 간단히 기록한다. 토큰·쿠키·서명 URL·사용자 계정 정보는 기록하지 않는다.

## Aside와 백그라운드 작업

Flow 작업은 Aside를 우선 사용하고 사용자가 작업 중인 화면·키보드·마우스를 점유하지 않는 것을 기본으로 한다. 기존 로그인과 프로젝트를 재사용한다. 브라우저 선택과 실제 백그라운드 제어 지원은 별개이며 스킬 설치만으로 제어 기능이 추가되지는 않는다.

1. Aside CLI가 있으면 현재 guide/repl 문서를 읽고 백그라운드 연결을 확인해 사용한다. 없으면 컴퓨터 사용 도구의 현재 앱·브라우저 목록을 확인한다. macOS Aside 식별자는 `at.studio.AsideBrowser`다. 앱 접근이 가능하면 현재 화면을 읽되 무관한 탭은 변경하지 않는다.
2. Aside가 브라우저 제어 대상으로 연결되어 있으면 도구 문서를 읽고 백그라운드 탭 접근 기능을 사용한다. 숨김 옵션은 해당 브라우저에서 지원되는 경우에만 사용한다. 다른 브라우저의 숨김 기능을 Aside에도 적용할 수 있다고 추정하지 않는다.
3. 네이티브 앱 접근만 가능한 경우 접근성 읽기와 실제 입력을 구분한다. 전면 전환이 필요한 클릭·키 입력·좌표 조작을 백그라운드 작업이라고 부르지 않는다. 지원 여부가 불명확하면 화면을 앞으로 가져오거나 시험 입력으로 사용자의 작업을 방해하지 않는다.
4. 백그라운드 입력을 지원하지 않거나 Aside가 연결되지 않았다면 그 지점만 설명하고 대본·이미지·음성·편집 등 독립 작업을 계속한다. 필요한 시점에 전면 조작 또는 백그라운드 가능한 다른 브라우저 중 사용자의 선택을 받는다. Chrome이나 인앱 브라우저로 조용히 전환하지 않는다.
5. 작업은 상태 확인 → 입력 → 결과 확인 순서로 진행한다. 생성 중에는 완료 상태에 맞춰 확인하며 연속 클릭과 중복 생성을 피한다. 도구 자체의 상태 대기를 우선하고 탐지 우회용 동작이나 임의 딜레이를 넣지 않는다.
6. 저장 창이 화면 점유를 요구하면 해당 단계만 알린다. 다운로드 설정을 임의 변경하지 않으며, 일시 변경을 승인받은 경우 원래 값을 기록하고 작업 후 복원한다. 실제 파일 저장과 미디어 확인 후 다운로드 완료로 보고한다.

2026-09-20 제작 기록에서는 720p 원본과 실제 1080p 업스케일 각 5개 및 Hypit/Hyperframes 편집 결과를 확인했다. 이 기록을 다른 환경의 브라우저 연결 성공 근거로 사용하지 말고 매 실행에서 현재 지원 상태를 확인한다.
